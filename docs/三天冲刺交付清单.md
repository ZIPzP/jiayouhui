> 适用：2026 第九届传智杯 AI WEB 网页开发挑战赛

> 更新口径：2026-11-04
> 原则：先完成可验证的 AI 闭环，再补材料；所有“已实现”必须能在测试或代码中找到证据。

## 一、三天后的最低交付状态

三天结束时，作品应具备以下可演示闭环：

1. 用户填写家庭约束，AI 生成逐日行程。
2. 生成前通过本地 RAG 检索适老、餐饮、景点和打包知识，结果页可查看来源。
3. 模型通过 Function Calling 自主选择知识检索、12306 和天气工具，页面可看到工具轨迹。
4. AI 管家的解释型问答采用流式输出，并显示“检索 / 调用工具 / 生成 / 降级”状态。
5. 可上传一张攻略截图，识别出目的地、日期、同行人和特殊要求，用户确认后回填表单。
6. 无 Key、模型超时或上游失败时，规则引擎和真实车次仍可产出完整行程。
7. 视频、PDF、README、环境模板、公开仓库和在线演示均达到提交要求。

| 场景 | 预期 |
| --- | --- |
| 无 Key 生成行程 | 返回规则行程、citations，不访问模型 |
| 模型工具调用 | 调用白名单工具，返回 `toolTrace` |

## 七、风险与回滚

| 风险 | 处理 |
| --- | --- |
| 新 Agent 使延迟增加 | 最多 4 轮、6 次工具；车次和天气并发；超过预算直接规则降级 |
| 模型别名或参数再次更新 | 启动日志记录实际模型；健康检查显示模型配置来源；保留规则路径 |
| 截图请求超过 512KB | 前端压到长边 1200px，WebP/JPEG 自适应压缩到 460KB；视觉接口上限 480KB |
| 上游 Key 失效 | 提供评审邀请码与本地规则行程双路径 |
| 地图域名限制 | 部署后在正式域名和评委网络各走一次地图工作流 |
| 新功能影响主链路 | 每个模块独立提交；`main` 不直接开发；失败可单独回退 |

## 八、答辩口径

不要把规则引擎说成“没有 AI 也能用”。正确口径是：

> AI 是家庭约束理解、知识检索、工具编排和个性化生成的核心；事实工具与规则引擎用于防编造和业务连续性，是 AI 系统的安全控制面。

不要声称：

- “RAG 让 token 必降 30%。”当前基线只注入单个目的地，应为检索命中率和引用可追溯负责。
- “已经实现 MCP Server。”除非最终真的完成协议层，否则只写 Function Calling。
- “真实多模态已验证。”在拿到真实 DeepSeek Key 前，只能写“代码与降级路径完成，待线上验证”。
- “所有 AI 输出绝对准确。”应说明事实工具、来源引用、结构校验和人工确认。
