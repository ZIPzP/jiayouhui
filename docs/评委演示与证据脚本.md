# 家游汇 · 评委演示与证据脚本

> 用途：5–8 分钟参赛视频、现场 3 分钟演示和评审答疑。
> 更新口径：2026-11-04
> 原则：先展示问题，再展示 AI 如何决策，最后展示失败时如何保持可信。

## 一、演示前准备

### 固定演示数据

建议统一使用：

- 出发地：上海
- 目的地：杭州
- 日期：录制前选择一个在 12306 预售期内、天气数据可覆盖的 3 天区间
- 同行：2 成人、1 老人、1 儿童
- 交通：高铁，上午出发
- 饮食：不吃辣
- 其他要求：老人腿脚不便，每天少走路；孩子需要午休

固定同一组输入，便于展示修改前后、工具调用和引用是否一致。

### 演示前检查

| 项目 | 检查 |
| --- | --- |
| 模型 | 实际模型为 `deepseek-flash`；Key 与 Base URL 属于同一服务商 |
| 网络 | 12306、天气、高德地图均可访问 |
| 浏览器 | Chrome / Edge 最新版，清理过期缓存 |
| 数据 | 最近一次行程、草稿和历史任务不会干扰演示 |
| 降级 | 另备一次无 Key 的规则生成录屏；本地已实测规则行程、RAG 依据和流式降级 |
| 敏感信息 | 录制画面不得出现 Key、邀请码、服务端路径和个人信息 |

### 01:30–02:50 RAG 与可追溯生成

画面：逐日行程、地图工作台和“依据”页签。

口播：

> AI 不是无来源地编攻略。与老人少走路、午休和饮食有关的内容来自本地知识片段；结果保留标题、摘要和可点击来源。

### 02:50–03:50 Agent 自主决策

画面：两个对比任务。

任务 A：

> 上海到杭州，高铁，上午出发。

预期：Agent 调用本地知识和 12306。

任务 B：

> 上海到杭州，明确选飞机且不关心高铁。

预期：不调用 12306，避免无意义出网。

口播：

> 工具选择来自模型对任务与上下文的判断；服务端只开放三个白名单工具，并限制轮次和调用次数。

证据：

- 两次 `toolTrace` 的工具集合不同。
- 未授权工具不会执行。

## 四、评委高频问题

### 为什么不是普通 LLM 调用？

回答要点：

- 家庭约束先结构化。
- RAG 检索本地知识并保留引用。
- Function Calling 自主选择事实工具。
- 车次、票价、天气不交给模型编造。
- 工具失败、JSON 失败和上游失败都有明确降级。

### 为什么用 BM25 而不是向量数据库？

回答要点：

- 当前知识规模小且字段明确，中文 bigram BM25 足够、可解释、冷启动快。
- 项目部署在低配置服务器，零运行时依赖降低运维风险。
- 后续数据扩大时可替换为混合检索，现有 citations 接口不变。

### 如何避免提示词注入？

回答要点：

- 工具白名单和参数 Schema。
- 工具轮次、调用次数、请求体与历史长度上限。
- 事实对象由服务端保留，不接受模型覆盖。
- 图片/文档内容只作为不可信输入，不具备调用工具的权限。

### 为什么保留规则引擎？

回答要点：

- 这是业务连续性和安全控制，不是“AI 可有可无”。
- AI 负责理解、检索、决策和解释；规则路径只处理模型不可用的异常场景。
- 失败时不扣用户次数，不伪造车次或天气。

### 3 天冲刺做了什么取舍？

回答要点：

- 优先 RAG、Function Calling 和流式，因为它们同时影响 AI 技术深度与 AI 交互体验。
- 保留成熟原生前端，不为框架指标推倒重来。
- 多模态聚焦“截图回填行程”的真实闭环，不做成本和收益不匹配的视频生成。
- 材料与代码并行验证，所有声明绑定测试或演示证据。

## 六、演示禁区

- 不展示 API Key、服务器配置、内部提示词和调试日志。
- 不展示模型原始 `reasoning_content`，只展示可读状态摘要。
- 不把 12306 参考班次说成用户出行日实时余票。
- 不把本地 Mock 通过说成真实 DeepSeek 已验证；不把 Function Calling 包装成已经部署 MCP Server。
- 不直接照搬开源 Skill 或项目代码；开源工具只用于开发、测试和审核流程。
